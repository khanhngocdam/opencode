# Codev2 divergences from upstream

## Policy

Prefer config, plugins, skills and agents, then additive `packages/codev-*`
packages, and edit upstream files only when those boundaries cannot implement
an integration. Every edited or deleted upstream file must have its own row
below in the same PR. New fork-only files belong in the module inventory.
Never rename internal `@opencode/*` packages or wire identifiers merely for branding.
Keep upstream attribution and license notices.

`codev.upstream.json` pins the upstream baseline, independently of `origin/dev`
(the fork PR base). `bun run check:divergences` checks cumulative changes against
that baseline, including working-tree changes. It requires the baseline Git object.

## Syncing with upstream

This v2 fork retains upstream history. The v1 release-tag patch procedure does
not apply. Do not truncate history or merge unrelated histories.

1. Start with a clean tree. Fetch `origin` and the upstream repository recorded
   in `codev.upstream.json`; create `sync-upstream` from `origin/dev`.
2. Record the target upstream commit. Verify it shares ancestry with the pinned
   baseline using `git merge-base`; stop if it does not.
3. Merge that target. For conflicts use the table below, preserving the upstream
   implementation around the smallest required Codev integration.
4. Update the pinned upstream commit/version only after resolving the merge.
   Reconcile renamed/deleted paths in this table; remove obsolete divergences.
5. Regenerate clients from `packages/client` if Protocol/HttpApi changed. Resolve
   manifests first, then regenerate the lockfile with Bun; never hand-edit it.
6. Run divergence checks, package tests and root `bun run check`. Verify Codev2
   does not discover or replace an OpenCode or Codev v1 service.
7. Open a conventional-title PR targeting `dev`, documenting target SHA, flags,
   migration effects and checks. Preserve upstream authorship and attribution.

## Fork-only modules

- `packages/codev-brand`: pure branding adapter and contract tests.
- `packages/codev-sandbox`: v1 sandbox providers copied for later integration; only `src/preview.ts`
  (`sandboxPreviewAvailability`, always unsupported in the preview, never boots a VM) is exported for v2 UI use.
- `sdks/vscode/script/pack-codev2.ts`: stages an isolated `Codev Code 2.0` extension (`codev.codev2`, `codev2.*`
  commands, `codev2` binary) in `sdks/vscode/dist-codev2/`; leaves the upstream extension untouched.
- `packages/cli/src/services/codev-updater.ts`: Codev updater (v1 parity): checks the `codev2-code` dist-tag on npm's configured registry, notifies by default, installs on request (or silently for a same-minor release under `autoupdate: true`) with `npm/pnpm/bun install -g codev2-code@<v>` only when the running binary belongs to that package; holds a second link to the running image on Windows; never removes a package.
- `packages/cli/test/codev-updater.test.ts`: no detection or install for source checkouts and other packages; npm upgrade targets only `codev2-code`; registry dist-tag lookup.
- `packages/cli/bin/codev2.cjs`: isolated command entry point.
- `packages/cli/script/release.ts` and `packages/cli/script/publish.ts`: local npm release of unscoped `codev2-code` (+ platform packages), staging from `dist/cli-*` without mutating the desktop CLI layout.
- `script/check-divergences.ts`: validates this registry against the pinned baseline.
- `.github/workflows/check-codev.yml`: validates divergence coverage with full history.
- `packages/codev-gateway`: gateway/SSO auth file, backend client, model limits and v2 provider config block (`providers`/`package`/`settings`/`capabilities`).
- `packages/tui/src/component/dialog-configure.tsx` and `packages/tui/src/util/configure-gate.ts` (tests in
  `packages/tui/test/configure-gate.test.ts`): Codev gateway configure dialog (SSO or API key; provider block merged
  into the global config file, key stored as a v2 credential) and its startup gate/retry helpers, including
  `shouldOpenConfigureGate` for the forced first-run gate.
- `packages/tui/test/codev-preload.ts`: test preload that turns the forced configure gate off for app fixtures.
- `packages/tui/test/configure-gate-app.test.tsx`: app-level tests that the forced configure gate opens on an install
  with no usable model, survives escape, and stays closed once a model exists.
- `packages/codev-skillhub`: SkillHub search/install/publish, Stack and Office installers.
- `packages/codev-upload`: session statistics push, log export and upload to the analysis backend.
- `packages/cli/src/commands/handlers/{configure,upload,migrate-v1}.ts`, `codegraph/{enable,disable,status,shared}.ts` (tests in `packages/cli/test/codegraph.test.ts`), `skill/*.ts` and `debug/stats.ts`: Codev command handlers.
- `packages/cli/test/codev-preload.ts` and `packages/tui/test/codev-preload.ts`: test preloads that keep Codev side effects (stats push, real gateway auth file, forced configure gate) out of upstream tests.
- `packages/cli/src/services/codev-flag.ts` and `packages/cli/test/codev-flag.test.ts`: flag guard for Codev commands that run without a Location; `codev_gateway`, `codev_skillhub` and `codev_upload` are on in every build, the rest only in local/dev.
- `.github/assets/codev-logo-{light,dark}.svg`: README wordmark (24x6 codev grid, navy or light "co", red "dev").
- `packages/desktop/icons/icon.svg`: source geometry of the brand-red Codev "C" app icon (copied from v1).
- Roboto and Roboto Mono woff2 subsets plus `OFL-Roboto{,-Mono}.txt` in `packages/app/public/assets/` and
  `packages/ui/src/assets/fonts/`: the only shipped UI faces (Viettel font-licensing directive).
- `patches/katex@0.18.11.patch`, `patches/@pierre%2Fdiffs@1.6.1.patch`, `patches/solid-sonner@0.3.1.patch`: strip
  Monotype font names from bundled library font stacks.
- `codev.upstream.json`: upstream and v1 source provenance.
- `CODEV-MIGRATION.md`: implementation status and acceptance gates.
- `script/bump-version.ts`: fork revision bump (`2.3.0` → `2.3.0-1`).
- `codev-v1-inventory.json`: source divergence inventory; `pending`, `port` and `review` entries are not implemented.
